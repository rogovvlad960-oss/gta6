# Автоматическая редакция @lesterdossier

**Статус: бесплатные облачные проверки развёрнуты; автопубликация выключена.** Источники доступны. Личность бота и право публикации проверены реально: GTA6NewsHustleBot — администратор с can_post_messages=true. Платный генератор и реальная доставка в Telegram ещё не проверены: нужен ключ редактора, бюджет и согласованный тест. Не называть систему готовой до завершения проверки всей цепочки.

[Три образца текста и изображений](samples/review.html) · [Расходы и выбранное облако](COSTS.md) · [Результаты доступа](SOURCE_ACCESS.md)

## Поведение

- Источники: `@leonidagov`, `@GTA6_m`, `@gta6deluxe`; публичные страницы `t.me/s/…`, без личной Telegram-сессии и платного агрегатора. Извлекаются реальные тексты, URL и даты с часовым поясом. Bot API для чтения чужой истории не используется.
- Обход до 8 страниц каждого источника за последние 48 часов. Если этот диапазон не покрыт, источник считается непроверенным и публикация блокируется. Альбомы могут занимать почти всю первую страницу. Цитата ответа отделена от собственного текста сообщения. Смена разметки с пустой выдачей — ошибка, не «новостей нет».
- Каждые три часа 09:00–21:00 Europe/Moscow: 09, 12, 15, 18, 21. Цель 2–3 новости, максимум 3/сутки, промежуток минимум 4 часа. Обычно это 09/15/21, если есть проверенные темы. Недобор разрешён; выдумывать новости для квоты нельзя. Ручное видео не генерируется и в лимит редакции не входит.
- Реклама, розыгрыши, подписи без новости, слишком старые сообщения и не-GTA6 материалы отбрасываются. Повторы проверяются по источникам, хешам текста, ключу события и пересечению слов. Перед подготовкой также читается публичная история целевого канала за 7 дней, в том числе подписи к ручным видео; повторяющийся текст отсеивается, темы передаются проверяющему. Это эвристики: реальные переписывания тем нужно оценить на пробной очереди перед запуском.
- Первичные ссылки из публикаций открываются только на конкретных доверенных доменах Rockstar, Take-Two, PlayStation, Xbox; дополнительно проверяется официальная страница VI. Отсутствующий оригинал X, YouTube, интервью или документа не заменяется догадкой. Автоматического поиска по всему интернету сейчас нет. Такие кандидаты остаются неподтверждёнными, а не получают статус факта.
- Модель сначала готовит текст, затем отдельный запрос проверяет его по тем же материалам. Цитаты дополнительно сверяются кодом с реально полученным текстом. Отдельная модельная проверка снижает риск ошибки, но не является доказательством истинности: её качество на живом API ещё нужно проверить. Слухи по умолчанию закрыты до утверждения стиля (`allow_rumors=false`); при разрешении обязательны явная атрибуция и пометка «СЛУХ / не подтверждено».
- Персонаж в тексте: сдержанный виртуальный Лестер, сухая ирония, без «мои инсайдеры сообщили». Это отдельная редакционная манера от нервной видеоозвучки. Существующий аватар сохранён. Фанатский проект не выдаёт себя за официальный канал Rockstar.
- Три образца имеют изображения и проверенные файлы с SHA256: официальный промо-арт помечен как арт, скриншоты вторичных публикаций — как скриншоты сообщений, не доказательства истинности слуха. Генерируемых картинок нет. Текущая автоматическая ветка отправляет **текст со ссылками**; `sendPhoto` подготовлен для утверждённых постов с конкретным изображением. Автоматическое изготовление новых карточек/поиск иллюстраций не включены: сначала утверждаются эти три образца.

## Локальная проверка без расходов

Нужен Python 3.11+ со стандартной библиотекой и системными сертификатами. Устанавливать pip-пакеты, Remotion или видеозависимости для редакции не требуется.

```sh
cd /workspace/gta6
python3 -m unittest discover -s newsroom/tests -v
python3 -m newsroom.editor audit
```

`audit` только читает источники; результаты — `out/newsroom/source-access.json` и `queue.json`. Токены ему не нужны. Ошибка хотя бы одного источника даёт ненулевой exit status. `bot-check` отдельно проверяет только права и ничего не публикует:

```sh
python3 -m newsroom.editor bot-check
```

Секрет `TELEGRAM_BOT_TOKEN` должен быть введён в защищённых настройках среды. Не вставлять его в команду, `.env` в Git, скриншот, задачу или переписку. Проверяются `getMe` → имя `GTA6NewsHustleBot`, `getChat` → канал, `getChatMember` → `administrator` и `can_post_messages=true` (либо owner).

## Подготовленный облачный запуск

Рекомендован бесплатный стандартный Linux runner GitHub Actions. Обоснование и расчёт в [COSTS.md](COSTS.md). Workflow размещён в `.github/workflows/newsroom.yml` на GitHub main. Audit и init-state реально прошли успешно на GitHub runner. Тестовый пост требует отдельного утверждения. Cloud bot-check подтвердил отсутствие TELEGRAM_BOT_TOKEN в GitHub Actions secrets; локально в Codex бот проверен и права есть.

1. Поместить модуль, тесты, config и workflow в default branch `main` существующего репозитория. Не загружать большие видеомастера или секреты. Текущие образцы и изображения — обычные небольшие файлы Git, не Actions artifacts.
2. В [GitHub Actions secrets](https://github.com/rogovvlad960-oss/gta6/settings/secrets/actions) сохранить **TELEGRAM_BOT_TOKEN**. Ключ берётся у владельца бота через BotFather. Значение не присылать в чат. Секрет в среде Codex и GitHub Actions secrets — разные хранилища: сохранение одного не копирует ключ в другое.
3. Один раз вручную запустить `init-state` через Actions → Lester Dossier newsroom → Run workflow. Будет создана отдельная orphan-ветка `newsroom-state` с `state.json`, без копирования видео и исходников. Повторная инициализация существующей ветки запрещена. Нужны права `GITHUB_TOKEN: contents: write` и политика репозитория, позволяющая запись Actions.
4. Запустить `audit`, затем `bot-check`. Убедиться, что источников три и права подтверждены. До создания состояния журнал ошибок виден в Actions; после — в state + Actions.
5. Утвердить стиль и один точный пост с изображением. SHA256 конкретных файлов для теста находятся в `samples/manifest.json`. Образцы явно датированы 05.11.2026; перед тестом сверить актуальность. Исправленный текст/изображение меняет хеш и требует нового утверждения.
6. После утверждения вручную запустить `test-post`: выбрать образец и передать `approved_hash`. До отправки заново читаются первичные страницы и исходные сообщения; цитаты должны сохраниться. Содержимое и фото не подменяются после согласования. Автоматического теста без утверждения нет.
7. Посмотреть реальный пост в канале: правильная картинка, подпись, ссылки, шрифт на картинке, отсутствие нежелательного превью/обрезки. Сверить `message_id` с журналом. Затем `confirm-test` с тем же хешем и message_id. Даже успешный Bot API сам по себе не открывает автопубликацию.
8. Для текстового API отдельно согласовать бюджет. Только затем добавить в GitHub secret `NEWSROOM_LLM_KEY`, variable `NEWSROOM_AI_SPEND_APPROVED=true`, изменить `monthly_budget_usd` с 0 на согласованную сумму и вручную проверить `draft` на реальном API. Редактор и проверяющий ещё не испытаны с пользовательским ключом. Модель, качество текста, usage и квитанции проверяются до включения.
9. После успешной всей цепочки и отдельного разрешения на автоматический режим установить `config.autopublish=true`, variables `NEWSROOM_STYLE_APPROVED=true` и `NEWSROOM_AUTOPUBLISH=true`. Проверить первый плановый запуск по журналу. Без любого из этих условий автоотправка закрыта. `NEWSROOM_AUTOPUBLISH=false` — аварийный выключатель; уже начавшийся send требует сверки.

Сейчас все разрешающие флаги отсутствуют, бюджет нулевой. Расписание при размещении workflow по умолчанию запускает только бесплатный `audit`. Публикация, генерация и расходы от одного добавления секретов не включатся.

## Состояние, повторы, ошибки

- Журнал сохраняется через GitHub Contents API с `sha` (compare-and-swap). Workflow имеет единую concurrency-группу и не прерывает предыдущую публикацию. Локальные файлы для разработки — только через `--state out/…json`, не использовать их как облачную историю.
- Ветка состояния публична, как и репозиторий. В ней ссылки на уже публичные источники, хеши текста/слов, ключи события, message_id, даты, статус, бюджеты и коды ошибок. Токенов, текстов черновиков и личных данных пользователей там нет. Если даже такие метаданные требуется скрывать — нужна отдельная приватная БД/репозиторий; этот вариант ещё не развёрнут.
- Порядок отправки: проверка личности/прав → запись `pending` → один `sendMessage`/`sendPhoto` → запись `published` с message_id. Нет атомарной транзакции между Telegram и GitHub, поэтому «exactly once» не обещается.
- Таймаут/потерянный ответ оставляет `uncertain`; сбой сохранения после успешной отправки оставляет persisted `pending`. Любой из них блокирует следующие публикации до ручной сверки. Автоматический resend запрещён.
- Сверка: открыть канал в интервале `at`, найти отправленный материал. Если есть — записать в state `published` и его message_id; если достоверно не был отправлен — `failed_confirmed`. Не сбрасывать весь state и не удалять историю ради повтора. Перед ручной правкой остановить workflow и сохранить копию ветки. Фальсифицировать подтверждение доставки нельзя.
- Ошибки: последние 200 кодов с UTC-временем плюс история Git-коммитов ветки и статус workflow. Не выводятся URL запросов Bot API (в URL находится токен), HTTP-тела ошибок или исключения сторонних библиотек. Исходный ненулевой exit status сохраняется. При недоступности самого state API ошибка остаётся в журнале Actions.
- Счётчик расхода месячный; сохраняется до платного вызова. Утраченный state не превращается в пустую историю: выполнение падает. Никаких автоматических повторов неизвестных платных запросов или отправок.
- Артефакты для скачивания очереди выключены. Их можно отдельно включить `NEWSROOM_SAVE_ARTIFACTS=true` после проверки storage; хранение 7 дней. В облаке без них есть счётчики в логе и постоянный state; черновик режима `draft` можно изучать через разрешённый артефакт. Локально файлы остаются в `out/newsroom/`.

## Что ещё обязательно проверить

- Реальный bot token, совпадение имени и `can_post_messages`.
- Развёртывание на GitHub runner, доступ оттуда к каждому `t.me/s` и официальным сайтам: здешняя удачная сеть не доказывает сеть другого облака.
- Реальный API выбранной модели, качество русского текста и независимой проверки, счётчик usage, стоимость и флаги ограничения расходов.
- Один согласованный тест с изображением, успешная доставка, видимый результат, запись в журнале, защита от повторного отправления, запуск по расписанию.

До этого редакция остаётся подготовленной реализацией, а не работающей автоматической службой.

## Исходники оформления образцов

`newsroom/samples/0*/preview.html` — исходная вёрстка каждой карточки; JPEG/PNG и `post.md` — готовые результаты. `samples/assets/provenance.json` хранит происхождение и хеши исходных изображений. Шрифт Manrope и его OFL-лицензия включены в assets. Образ персонажа взят из существующей аватарки, новое лицо не генерировалось.

Для разработки карточек отдельно сохранены `tools/capture_samples.py` и `tools/render_samples.py` (нужны Playwright, Chromium, Pillow; они не нужны рабочему боту). Capture повторно снимает настоящие публичные сообщения, render использует сохранённые assets и строит карточки локально. Новые скриншоты сначала проверяются человеком, затем заменяются в assets. Повторная вёрстка обновляет хеши и требует нового согласования тестового поста. Запросы браузера к публичным источникам в capture доставляются через urllib с проверкой TLS, отключения проверки сертификатов нет. Локальный HTTP-сервер render используется только внутри процесса и не является размещением сервиса для пользователя.
